# Requirements register

- [`requirements.yaml`](requirements.yaml) — one entry per `FR-nn`/`NFR-nn` from the PRD,
  extracted once and then hand-maintained: priority band, phase, status, and (where a
  test isn't a plausible way to demonstrate an infrastructure/process requirement) an
  `evidence:` path.
- [`traceability.md`](traceability.md) — generated by
  `scripts/traceability_check.py`, which also runs in CI to keep the two in step. Do not
  hand-edit `traceability.md`; regenerate it with `uv run python
  scripts/traceability_check.py` from the repo root after editing `requirements.yaml` or
  adding a `@pytest.mark.req(...)` marker.

See PRD §"Reading guide" for the requirement-numbering convention this register follows,
and `CONTRIBUTING.md`'s "Definition of done" for when a requirement moves to
`implemented`.
