# Requirements register

- [`requirements.yaml`](requirements.yaml) — one entry per `FR-nn`/`NFR-nn` from the PRD,
  extracted once and then hand-maintained: priority band, phase, status, and (where a
  test isn't a plausible way to demonstrate an infrastructure/process requirement) an
  `evidence:` path.
- `traceability.md` — generated by `scripts/traceability_check.py`, which also runs in CI
  (the `traceability` job in `.github/workflows/docs.yml`) to keep the two in step. Not
  committed (issue #126: it diverged byte-for-byte between branches with different
  `@pytest.mark.req` markers, causing merge conflicts in a file nobody hand-edits anyway)
  — CI uploads it as a build artefact on every run. Regenerate it locally with `uv run
  python scripts/traceability_check.py` from the repo root after editing
  `requirements.yaml` or adding a `@pytest.mark.req(...)` marker.

See PRD §"Reading guide" for the requirement-numbering convention this register follows,
and `CONTRIBUTING.md`'s "Definition of done" for when a requirement moves to
`implemented`.
